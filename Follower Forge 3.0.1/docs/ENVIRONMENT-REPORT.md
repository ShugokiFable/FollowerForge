### Deployment manifest (authoritative file→mod map)

`Data\vortex.deployment.json` — **88,738,271 bytes** (must be stream-parsed, never loaded whole):

```json
{
  "instance": "16b0d71b-…",
  "version": 1,
  "deploymentMethod": "hardlink_activator",
  "gameId": "skyrimse",
  "stagingPath": "C:\\Users\\karlo\\AppData\\Roaming\\Vortex\\skyrimse\\mods",
  "targetPath": "c:\\…\\Skyrim Special Edition\\Data",
  "files": [ { "relPath": "…", "source": "<staging mod folder name>", "target": "", "time": … }, … ]
}
```

- `deploymentMethod: hardlink_activator` → deployed files ARE the staging files (same inode). Writing to either would corrupt the install ⇒ the app treats **both** as read-only.
- `source` is the staging mod-folder name ⇒ direct provenance for every loose file.
- Leftover `vortex.deployment.json.*.tmp` files exist; parser must ignore them.

### Active-profile detection strategy (validated against this install)

Vortex keeps the active profile in its LevelDB state (`%APPDATA%\Vortex\state.v2`) which is unsafe to read while Vortex runs. Follower Forge instead:
1. Enumerates `Vortex\skyrimse\profiles\*`.
2. Reads the game-runtime `%LOCALAPPDATA%\Skyrim Special Edition\plugins.txt`.
3. The profile whose `plugins.txt` content matches the runtime file is active (single-profile installs trivially match).
4. Cross-checks `vortex.deployment.json.deploymentTime` freshness and reports divergence instead of guessing.

### jslot format (sampled: `A1_Nord_Natalie.jslot`)

Top-level keys: `actor`, `faceTextures`, `headParts`, `modNames`, `mods`, `morphs`, `tintInfo`, `version`.
- `mods`: `[{ "index": 0, "name": "Skyrim.esm" }, …]` — **the master/requirement list** (sample requires `High Poly Head.esm`, `KS Hairdo's.esp`, `Koralina's Eyebrows.esp`).
- `headParts`: `[{ "formId": …, "formIdentifier": "Plugin.esm|05150F", "type": 0-… }]`.
- `actor`: `{ "hairColor": …, "headTexture": "Skyrim.esm|03B522", "weight": 100 }`.
- Confirms the spec rule: a jslot alone gives head-part refs + morphs but **not** the baked sculpt — the matching CharGen NIF/DDS is required for exact reproduction.

### CharGen NIF format (sampled: `A1_Nord_Natalie_head.nif`)

`Gamebryo File Format, Version 20.2.0.7` (SSE), root `BSFadeNode`, head geometry `BSDynamicTriShape`, `NiSkinInstance` present. NiflySharp 2.x supports this format.

## 9. Risks / decisions

1. **88 MB deployment manifest** → Utf8JsonReader streaming; cache parsed result in SQLite keyed by `deploymentTime`.
2. **2,882-plugin load order** exceeds the game's own limits only via ESL slots — Mutagen handles FE indexing; indexing must be lazy/streamed, not all-in-RAM.
3. **Voice files in BSA** → archive reader required in Phase 1 (not deferred to Phase 5).
4. **Hardlink deployment** → double protection: path-prefix write guard for BOTH game Data and staging.
5. Mutagen/NiflySharp exact API names are verified by compilation, never assumed in docs.
